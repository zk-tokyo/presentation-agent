# プリミティブは組み合わせられる

<div class="text-sm text-gray-500 mt-1 mb-4"><strong>Programmable Cryptography</strong> の核心は、単独では持ち得ない性質を複数プリミティブの<strong>目的指向の合成</strong>で得ること。</div>

<table class="text-sm">
<thead>
<tr>
<th>合成</th>
<th class="w-1/4">何が足されるか</th>
<th>代表例</th>
</tr>
</thead>
<tbody>
<tr>
<td class="font-black text-amber-700">vFHE = ZK + FHE</td>
<td>計算委託 <strong>+ 計算の正しさ</strong></td>
<td>サーバーが暗号文を正しく演算した証明 (Greco / EagleEye)</td>
</tr>
<tr>
<td class="font-black text-amber-700">leanVM = XMSS + ZK</td>
<td>耐量子署名 <strong>+ 集約・検証</strong></td>
<td>ハッシュベース署名を zkVM で再帰集約 (Ethereum の PQ 移行)</td>
</tr>
<tr>
<td class="font-black text-amber-700">co-SNARK = ZK + MPC</td>
<td>正しさの証明 <strong>+ 入力の秘匿</strong></td>
<td>複数者の secret witness から 1 つの SNARK (World ID)</td>
</tr>
<tr>
<td class="font-black text-amber-700">zkML = ZK + ML</td>
<td>推論 <strong>+ 実行の検証</strong></td>
<td>モデル推論が正しく行われた証明</td>
</tr>
<tr>
<td class="font-black text-amber-700">threshold FHE = MPC + FHE</td>
<td>計算委託 <strong>+ 鍵の分散</strong></td>
<td>復号鍵を単一管理者に集中させない (Zama)</td>
</tr>
</tbody>
</table>

<div class="mt-4 text-md text-gray-700 max-w-5xl">「<strong class="text-amber-600">A は何を保証し、B は何を秘匿するか</strong>」を分解すれば、合成は設計できる。</div>
