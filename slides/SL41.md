# グループワーク② 回答例：攻撃コードを渡さず脆弱性を証明

<div class="text-sm text-gray-500 mt-1 mb-4">攻撃コード <strong>x</strong> を witness に隠したまま「<strong>P を破る入力が存在する</strong>」だけを証明する。<strong class="text-amber-700">zkVM</strong> が任意プログラム実行を入力秘匿のまま証明できる。</div>

<div class="flex items-stretch justify-center gap-2 max-w-6xl mx-auto">

<div class="flex-1 p-4 bg-green-50 rounded-xl border border-green-200">
<div class="text-[10px] font-bold tracking-widest text-gray-400 mb-1">① 研究者（prover）</div>
<div class="text-md font-black text-gray-900 mb-2">witness を用意</div>
<div class="text-sm text-gray-700 leading-relaxed">攻撃コード <strong>x</strong> を <strong>witness</strong>（秘匿入力）に。プログラム <strong>P のハッシュ</strong>を public に固定。<span class="text-gray-500">x は誰にも渡さない。</span></div>
</div>

<div class="flex items-center text-2xl text-amber-500 font-black px-1">&#9654;</div>

<div class="flex-1 p-4 bg-amber-50 rounded-xl border border-amber-200">
<div class="text-[10px] font-bold tracking-widest text-gray-400 mb-1">② zkVM guest</div>
<div class="text-md font-black text-gray-900 mb-2">P(x) を実行し証明</div>
<div class="text-sm text-gray-700 leading-relaxed">P を x で実行し「<strong>脆弱状態に到達</strong>（クラッシュ / assert 失敗 / メモリ安全違反）」を判定。その実行を <strong>ZK 証明 π</strong> にまとめる。</div>
</div>

<div class="flex items-center text-2xl text-amber-500 font-black px-1">&#9654;</div>

<div class="flex-1 p-4 bg-blue-50 rounded-xl border border-blue-200">
<div class="text-[10px] font-bold tracking-widest text-gray-400 mb-1">③ ベンダー（verifier）</div>
<div class="text-md font-black text-gray-900 mb-2">π を検証</div>
<div class="text-sm text-gray-700 leading-relaxed"><strong>π</strong> を検証し「<strong>∃x: P(x) が bug 到達</strong>」を確信。<span class="text-gray-500">攻撃コード x は一切見ずに脅威を確認できる。</span></div>
</div>

</div>

<div class="mt-5 p-4 bg-gray-50 rounded-xl border border-gray-200 max-w-6xl mx-auto text-sm text-gray-700 space-y-1.5">
<div><span class="text-amber-600 font-black mr-1">信頼境界</span>境界を越えるのは <strong>π</strong> と <strong>P のハッシュ</strong>だけ。攻撃コード x は研究者のローカルに留まる。</div>
<div><span class="text-amber-600 font-black mr-1">なぜ zkVM</span>x を witness に隠したまま「P を x で走らせると bug に到達する」という<strong>任意のプログラム実行</strong>をそのまま証明できる。責任ある開示（盗用させず存在だけ示す）を実現。</div>
<div><span class="text-red-600 font-black mr-1">落とし穴</span>証明者コスト（実行トレース化は重い → precompile / 再帰）／ <strong>P の同一性</strong>（配布中バイナリと一致する binding が必須）／ <strong>「脆弱」の定義</strong>（bug 述語が緩いと空虚な主張も通る）。</div>
</div>

<div class="mt-3 text-center text-sm text-gray-700 max-w-6xl mx-auto"><strong class="text-gray-900">共通教訓</strong>：ZK は信頼を<strong>消さず再配分</strong>する。① は「データを隠す（機密性）」、② は「秘密の入力の性質を見せずに証明」。何を信じることになるかを設計時に言語化せよ。</div>

<div class="absolute bottom-3 left-6 text-[10px] text-gray-400 leading-tight max-w-3xl">
Sources: Proof of Exploit（攻撃コード存在証明）パターン — zkVM で脆弱性の存在を入力秘匿のまま証明
</div>
