# セキュリティ：Zcash の偽造脆弱性

<div class="text-sm text-gray-500 mt-1 mb-4">zk-SNARK 実装の <strong>soundness</strong> を破るバグ。匿名通貨が<strong>無制限・不可視に偽造</strong>されうる状態が、数年間気づかれず存在した。</div>

<div class="grid grid-cols-3 gap-4 max-w-6xl mx-auto">

<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-black text-gray-900 mb-2">原因</div>
<div class="text-sm text-gray-700 leading-relaxed">[BCTV14] のパラメータ生成が<strong>余分な要素</strong>を出力し soundness を侵害。本来 prover が使わないはずの要素が、consistency check の回避を許し、ある命題の証明を<strong>別命題の「正しく見える」証明</strong>に変換できた。</div>
</div>

<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-black text-gray-900 mb-2">影響</div>
<div class="text-sm text-gray-700 leading-relaxed">shielded な ZEC を<strong>無制限に偽造</strong>可能。秘匿取引ゆえ偽造は検知が困難。2018-03 に暗号研究者 <strong>Ariel Gabizon</strong> が発見（CVE-2019-7167）。専門家の長年の解析を擦り抜けていた。</div>
</div>

<div class="p-4 bg-amber-50 rounded-xl border border-amber-200">
<div class="text-md font-black text-gray-900 mb-2">対応</div>
<div class="text-sm text-gray-700 leading-relaxed"><strong>Sapling</strong> アップグレード（2018-10-28 / block 419200）で <strong>Groth16</strong> へ移行し封鎖。修正意図を伏せて静かにデプロイ、2019-02 に公表。「偽造は発生していない」と判断（Sprout 残高を監視）。</div>
</div>

</div>

<div class="mt-5 p-3 bg-gray-50 rounded-xl border border-gray-200 max-w-6xl mx-auto text-sm text-gray-800">
<span class="text-amber-600 font-black mr-1">&#9654;</span>教訓：壊れたのは <strong>soundness（正しさ）</strong>で zero-knowledge ではない — 両者は別軸。<strong>trusted setup / パラメータ生成は ZK 最大の攻撃面</strong>であり、「proof が verifier を通る」ことと「proving system が健全」は別問題。
</div>

<div class="absolute bottom-3 left-6 text-[10px] text-gray-400 leading-tight max-w-3xl">
Sources: Electric Coin Co. "Zcash Counterfeiting Vulnerability Successfully Remediated" (2019) ｜ CVE-2019-7167 ｜ Ben-Sasson, Chiesa, Tromer, Virza [BCTV14] USENIX Security 2014
</div>
