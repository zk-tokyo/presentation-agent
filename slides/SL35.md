# グループワーク②：攻撃コードを渡さず「脆弱性の存在」を証明する

<div class="p-5 bg-amber-50 rounded-xl border border-amber-200 max-w-6xl mx-auto mt-2">
<div class="text-amber-700 font-black mb-1">お題</div>
<div class="text-sm text-gray-800 leading-relaxed">あるセキュリティ研究者が、広く使われるプログラム <strong>P</strong> に深刻な脆弱性（クラッシュ / 任意コード実行）を見つけた。ベンダーに「<strong>確かに動く攻撃コードを持っている</strong>」と示して報奨金を得たい。だがその<strong>攻撃コード（脆弱性を突く入力）</strong>をそのまま渡すと、<strong>パッチ前に盗用・悪用</strong>される恐れがある。<strong>攻撃コードを秘匿したまま「P を破る入力が存在する」</strong>ことを検証させたい。— <strong>zkVM</strong> でこのスタックを設計せよ。</div>
</div>

<div class="p-5 bg-white rounded-xl border border-gray-200 shadow-sm max-w-6xl mx-auto mt-5">
<div class="font-black text-gray-900 mb-2">進め方</div>
<div class="space-y-1.5 text-sm text-gray-700">
<div class="flex items-start gap-2"><span class="text-amber-500 font-black mt-0.5">1</span><span>要件を言語化（<strong>Secret = 攻撃コード（入力 x）</strong> / <strong>Public = P と「破れる」という主張</strong>）</span></div>
<div class="flex items-start gap-2"><span class="text-amber-500 font-black mt-0.5">2</span><span>zkVM のゲストプログラムは何を実行する？（P を入力 x で走らせ、<strong>脆弱な状態に到達</strong>したことを判定）</span></div>
<div class="flex items-start gap-2"><span class="text-amber-500 font-black mt-0.5">3</span><span><strong>ユーザーフローを書き出す</strong>（研究者→ guest 実行→ proof 生成→ 検証者、<strong>境界を越えるのは π のみ</strong>を時系列で）</span></div>
<div class="flex items-start gap-2"><span class="text-amber-500 font-black mt-0.5">4</span><span>落とし穴を 1 つ（証明者コスト / P の同一性 / 「脆弱」の定義）</span></div>
</div>

Speaker Notes:
ホワイトボードのグループワーク②（zkVM テーマ）= Proof of Exploit。GW① が「データを隠す(FHE)= 機密性」だったのに対し、GW② は「秘密の入力が性質を満たすことを、入力を見せずに証明する」= zkVM ならではの設計。責任ある開示(脆弱性を盗用させずに存在だけ示す)が動機。この GW はそもそも primitive が zkVM に固定されているため、primitive 選択そのものより「zkVM で何を witness/public にするか」の設計に集中させる。成果物はユーザーフロー図: 研究者(prover)→ guest プログラムで P(x) 実行→ proof 生成→ 検証者(vendor) の時系列を描き、信頼境界を越えるのは π だけ (攻撃コード＝入力 x は境界内に留まる) を矢印で明示させる。
【模範解の方向性（運営用）】
- 要件: Actors = 研究者(prover)・ベンダー(verifier)。Secret Inputs = 攻撃コード（入力 x）。Public Outputs = プログラム P(または P のハッシュ)と「∃x: P(x) が脆弱状態に到達」という述語。Trust Boundary = x は誰にも見せない、proof が存在を保証。
- guest プログラム: P を入力 x で実行し、(a) クラッシュ/assert 失敗/メモリ安全違反など「脆弱状態」に到達したことを検出 → その実行を zkVM が証明。RISC-V 系 zkVM なら P の実バイナリをほぼそのまま guest にできる。
- なぜ zkVM か: x を witness に隠したまま「P を x で走らせたら bug に到達する」という任意のプログラム実行をそのまま証明できる。x を渡さずに第三者が脅威を確認。
