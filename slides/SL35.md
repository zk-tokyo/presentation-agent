# POD2 の仕組み：演繹で証明を積む

<!--
Speaker Notes:
前ページのフローの「内部」を解説する仕組みスライド。POD2 の本質は「演繹的証明（deductive proving）」= 二段証明（two-column proof）形式。
【3 カードの線形フロー】
  ① SignedPOD（源泉/葉）— 発行者が key-value に EdDSA 署名。エントリは Merkle tree 化され、個別エントリだけを選択開示できる（POD1 相当のデータ源泉）。
  ② Statements × Operations（演繹エンジン）— Statement は値への主張（Equal/NotEqual/Lt/Gt/Sum/Product/Contains/SignedBy/Hash 等の組み込み型）。Operation はその主張を既存の主張から導く演繹規則（EqualFromEntries, TransitiveEqual, LtFromEntries, ContainsFromEntries…）。Custom Predicate はユーザが複数 statement の AND/OR で自作する述語で、自己・相互再帰が可能（グループ内で既出/自身/同グループに依存制限）。一度導入すれば子孫 POD でも使える。
  ③ MainPOD（再帰証明）— 入力の SignedPOD / 他 MainPOD を回路内で再帰検証し、演繹した statement を ZK 証明にまとめる。MainPOD 自体が POD なので次の MainPOD の入力に再投入でき、これが「証明の連鎖／合成」を生む。
【実装スタック】コンパイラの比喩。Frontend = 人間可読型（string/int/bool）で POD 宣言を受け中間表現へ（Rust→LLVM-IR 相当）。Middleware = 強い型付けの Statement/Operation を定義、frontend/backend に非依存（LLVM-IR 命令）。Backend = 証明系に依存する署名・証明（LLVM-IR→アセンブリ）。証明系は初版 Plonky2（透明・再帰向き）。on-chain 検証は pod2-onchain が Groth16 で wrap して検証コストを下げる。
【学術的正確性メモ】「再帰 = Plonky2」「on-chain 圧縮 = Groth16 wrap」は別レイヤーの利点として分けて語る。Plonky2 は trusted setup 不要（transparent）= 質問が来たら即答できるように。
【講義での位置づけ】POD2 は 0xPARC の Programmable Cryptography／データ主権の応用例。前ページのユースケースフローと合わせ、「開発者は回路を書かず、生データを出さず、証明を再帰合成できる」を締めに。
-->
