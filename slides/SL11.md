# 周辺/対比

<div class="grid grid-cols-2 gap-5 mt-4 max-w-6xl mx-auto">

<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">co-SNARK <span class="text-xs font-normal text-gray-500">(in production)</span></div>
<div class="text-sm text-gray-700">既存 Circom / Noir 回路を<strong>変更せず</strong>、複数 party の secret-shared witness から 1 つの SNARK を協調生成。World ID: 虹彩 (secret) を 3-party MPC で uniqueness check → Groth16 で証明</div>
</div>

<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">zkTLS family</div>
<div class="text-sm text-gray-700">Web2 の application data を Web3 で検証可能に。<strong>TLSNotary</strong> (notary が TLS key を MPC 共有・選択開示) / <strong>vlayer</strong> (Web/Email Proofs) / <strong>Reclaim</strong> (制約環境)</div>
</div>

<div class="p-4 bg-amber-50 rounded-xl border border-amber-200">
<div class="text-md font-bold text-amber-700 mb-1">MPCitH &ne; MPC</div>
<div class="text-sm text-gray-700"><strong>MPCitH</strong> (IKOS 2007): MPC を頭の中でシミュレートし transcript を commit+open する <strong>proof technique</strong> (prover 1名)。NIST PQ 署名候補: Picnic / FAEST / SDitH。<br/><span class="text-gray-500">co-SNARK は MPC を <strong>trust model</strong> として使う (prover 複数)</span></div>
</div>

<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">VOLE-ZK</div>
<div class="text-sm text-gray-700">TLSNotary が backend を GC → <strong>QuickSilver (VOLE-ZK)</strong> に切替。通信量は回路サイズに線形だが prover が極めて軽い → モバイル / 組込 / ストリーミング向け (Wolverine / Mac'n'Cheese)</div>
</div>

</div>
