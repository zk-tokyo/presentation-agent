Speaker Notes:
【概要】POD2 = 0xPARC の Provable Object Data 第2世代。任意の key-value データに発行者が署名した「SignedPOD」を起点に、内容を明かさずに「年齢≥18 かつ正規発行者の署名つき」のような主張だけを ZK 証明し、その証明（MainPOD）をさらに別の証明の入力に再投入できる。ZK の第3の効用 = interoperability（相互運用性）を狙う「universal cryptographic adapter」構想。Zupass / Frogcrypto / Devcon Passport などで稼働中。
【前提】図は概念フロー。実装の証明系は Plonky2（再帰）、on-chain 検証時は Groth16 で wrap。GPC = General Purpose Circuits（プリコンパイル済み汎用回路 = アプリ固有回路も trusted setup も不要）。
【図の読み方】左→右の線形フロー。Issuer（署名鍵を持つ発行者）→ SignedPOD（署名済みクレデンシャル）→ Holder（ウォレット）→ GPC/MainPOD（証明生成器）→ Verifier（検証するアプリ / オンチェーン）。緑の破線枠「ローカル」= 秘密データがここから外に出ないことを表す。境界を越えるのは証明 π だけ。
【各 phase の物語】
  phase 0 発行 — Issuer が key-value に EdDSA 署名し SignedPOD を発行（エントリは Merkle tree 化）。
  phase 1 保有 — Holder がウォレットに保持し、発行者公開鍵で署名を検証。
  phase 2 要求 — Verifier が「age ≥ 18 ∧ signedBy(issuer)」という述語（predicate）を proof request として提示。
  phase 3 証明 — Holder が SignedPOD を GPC に通し MainPOD を生成。秘密データ（生年月日など）はローカルに留まる。
  phase 4 検証 — 境界を越えるのは π のみ。Verifier が検証し accepted。age≥18 だけ開示・他は秘匿。
  phase 5 合成 — MainPOD 自体が POD なので、別の MainPOD の入力に再投入できる（再帰合成）。これが「adapter」たる所以。
【講義での強調点】① 開発者は回路を書かない（GPC が汎用）。② 公開されるのは「主張の真偽」だけで生データは出ない。③ 証明が再帰的に合成でき、複数ソースのデータを跨いだ主張を積み上げられる。④ 次ページで内部の仕組み（演繹モデルと3モジュール）を解説する。
-->
