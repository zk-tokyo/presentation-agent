Speaker Notes:
理論から実装への橋渡し。SL28 の決定木で primitive を選んだ後、実際に手を動かすためのツール群。このスライドは Programmable Cryptography (プリミティブの目的指向な合成) に焦点を絞り、ZK 単体と、2 primitive の合成 (co-SNARK, Threshold FHE, Verifiable FHE) だけを扱う。素の MPC ツール (MP-SPDZ 等) や素の FHE ライブラリ (OpenFHE 等) はここでは扱わない — それらは「合成」ではなく単一 primitive の実装なので、本講義の合成というテーマからは外れる。列は ZK → co-SNARK (ZK+MPC) → Threshold FHE (MPC+FHE) → Verifiable FHE (ZK+FHE) の順で、ZK/MPC/FHE 三角形をひと回りする配置。
【ZK】Circom+snarkjs は最も裾野が広い組み合わせ (iden3 発、Groth16 中心)。RISC0 は zkVM の SDK (Part 2 で既出) をここでは「実装ツール」として再登場させる — 任意のプログラム実行を証明したいなら回路を手書きせずこちらを使う。
【co-SNARK (ZK+MPC)】co-snarks は TACEO のプロダクトで、World ID の実装基盤として本講義に既出。witness を分散したまま複数者が協調して1つの SNARK 証明を生成する。
【Threshold FHE (MPC+FHE)】threshold-fhe は Zama の OSS。FHE は「計算委託」、MPC は「復号鍵の分散」を担当 — 誰か1人が鍵全体を持つと信頼が集中するのを、鍵生成・復号を複数ノードの MPC に分散して防ぐ。Zama の FHEVM (confidential smart contract) の KMS 基盤として稼働。
【Verifiable FHE (ZK+FHE)】EagleEye は本講義で既出の実装アプローチ。FHE 演算トレースを Plonk 系制約に変換して証明する (研究・実験段階であり、汎用製品版ライブラリではない点は注意)。
【締め】ライブラリ選定はプリミティブ選択の後工程。trusted setup 要否・言語エコシステム (Rust/C++/JS)・用途 (教育/研究/本番) で絞り込む。次は実装時に必ず点検すべき性能・セキュリティ・プライバシー・法律の注意点に進む。
