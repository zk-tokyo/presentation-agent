<div class="space-y-2 text-sm text-gray-700">
<div class="flex items-start gap-2"><span class="text-red-400 mt-0.5">&#9679;</span><span><strong>Groth16 / KZG</strong> は楕円曲線 DLP に依存</span></div>

<div class="space-y-2 text-sm text-gray-700">
<div class="flex items-start gap-2"><span class="text-green-500 mt-0.5">&#10003;</span><span><strong>STARK / FRI</strong> は collision-resistant hash のみに依存</span></div>
<div class="flex items-start gap-2"><span class="text-green-500 mt-0.5">&#10003;</span><span>Grover の sqrt 加速はあれど概ね安全 (RISC0 / SP1 / Plonky3)</span></div>

<div class="mt-6 p-4 bg-amber-50 rounded-xl border border-amber-200 max-w-6xl mx-auto">
<div class="text-md font-bold text-amber-700 mb-2">移行アイデア &mdash; PKC を ZK で wrap (PKC × ZK の Programmable Cryptography)</div>
<div class="text-sm text-gray-700 leading-relaxed">
既存の Groth16 / KZG <strong>検証回路そのものを zkVM 上で実行</strong>し、その実行を STARK で証明する。<br/>
<span class="text-gray-500">内側 = 古典 PKC ベース SNARK (Shor で破れる) ／ 外側 = STARK / FRI ベース zkVM (PQ-secure)</span><br/>
&rArr; 既存資産を壊さず PQC migration を実現。「量子計算機が来たら ZK は終わり」<strong class="text-amber-700">ではなく設計選択の問題</strong>。
</div>
</div>
