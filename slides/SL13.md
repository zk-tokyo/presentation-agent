Speaker Notes:
証明・検証系アプリの最も古典的な例として Tornado Cash の「仕組み」を、アプリ俯瞰（前スライド）の直後に深掘りする。zk-SNARK 応用の教科書的構成であり、ここで覚える語彙は後半の World ID で再利用される。
【動機】Ethereum は全送金が公開台帳。アドレス A → B の資金移動は誰でも追える。Tornado Cash は預入アドレスと引出アドレスの繋がりを暗号的に切る固定額ミキサー（1 ETH / 10 ETH 等のプール単位）。
【① 預入】ユーザーはローカルで secret k と nullifier r を乱数生成し、commitment C = H(k, r) だけをコントラクトに提出（k, r はチェーンに出さない）。同時に固定額 1 ETH を送る。C は Merkle tree の葉として追記される。
【② anonymity set】同じ固定額を預けた全員の commitment が 1 本の Merkle tree を成す。これが匿名集合。預入者が多いほど「誰の引出か」の候補が増え、匿名性が上がる。
【③ 引出】まったく無関係な新アドレス A′ から zk-SNARK を提出。証明内容は (1) 自分は k, r を知っており、その commitment C が現在の tree に含まれる（Merkle membership 証明）、(2) nullifierHash = H(r) を公開する、の 2 点。コントラクトは root と proof を検証し、nullifierHash が未使用なら 1 ETH を払い出す。ガス代は relayer に肩代わりさせれば、A′ は ETH 残高ゼロの新規アドレスでよい＝資金の出所を持たない。
【鍵の二点】どの葉を使ったかは証明から分からない（zero-knowledge）。nullifierHash は本人だけが作れる一方、一度使うと記録され同じ預入を二度引き出せない（double-spend 防止）。
【前振り】この commitment + nullifier + Merkle membership という 3 点セットは、後半に出る World ID の Semaphore とまったく同じ語彙。だから Tornado Cash を理解すれば World ID の匿名性機構は復習になる。ただし「暗号は正しくてもプライバシーは漏れる」点を次スライドで警告する。
