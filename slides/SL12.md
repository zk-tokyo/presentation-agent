Speaker Notes:
次スライド（仕組みの詳細）の前に、Tornado Cash を「ユーザーが何をするか」の 1 連の流れとして体感させる導入アニメ。図は 4 phase で morph する。
【動機】Ethereum は全送金が公開台帳。アドレス A → B の資金移動は誰でも追える。Tornado Cash は預入アドレスと引出アドレスの繋がりを暗号的に切る固定額ミキサー（1 ETH / 10 ETH 等のプール単位）。
【各 phase の物語】
phase 0 — 預入：User A がローカルで secret k と nullifier r を乱数生成し、commitment C = H(k, r) だけをコントラクトに提出して固定額 1 ETH を送る。note (k, r) は手元に保存し、チェーンには出さない。C は Merkle tree の葉として追記される（この時点では「A が C を預けた」ことは公開＝リンクが見えている）。
phase 1 — 匿名集合が育つ：同じ固定額を預けた全員の commitment が 1 本の Merkle tree を成す。預入者が増えるほど「誰の引出か」の候補が増え、自分の C は集合に埋もれる。匿名性 = 集合の大きさ。
phase 2 — 引出：まったく無関係な新アドレス A′ から zk-SNARK π を提出。証明内容は (1) 自分は note (k, r) を知り、その C が現在の tree に含まれる（Merkle membership）、(2) nullifierHash = H(r) を公開、の 2 点。どの葉かは伏せたまま（zero-knowledge）。ガス代は relayer が肩代わりするので A′ は残高ゼロの新規アドレスでよい。
phase 3 — 支払：コントラクトは root と π を検証し、nullifierHash が未使用なら 1 ETH を A′ に払い出す。これで預入 A と引出 A′ のオンチェーン・リンクは切れる。nullifierHash は記録され、同じ note の二重引出は不可（double-spend 防止）。
【前振り】commitment + nullifier + Merkle membership の 3 点セットは次スライドで数式・図解として詳述し、後半の World ID（Semaphore）でも再利用する。さらに「暗号は正しくてもプライバシーは漏れる」限界を SL14 で警告する。
-->
