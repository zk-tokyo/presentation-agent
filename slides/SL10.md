# B. Ethereum PIR ②

<div class="text-sm text-gray-600 mt-1 mb-3"><strong>PIR</strong>: どのインデックスを引いたかをサーバーに隠したまま DB から値を取得。多くの効率的構成は <strong>FHE / LWE ベース</strong>。</div>

<div class="grid grid-cols-3 gap-4 max-w-6xl mx-auto">
<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">RPC プライバシー</div>
<div class="text-sm text-gray-700">「特定アドレスの残高を問い合わせる」事実をノード運営者に隠す (Helios light client + PIR)</div>
</div>
<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">Light Client クエリ匿名化</div>
<div class="text-sm text-gray-700">チェーン状態のサブセット問い合わせを匿名化</div>
</div>
<div class="p-4 bg-white rounded-xl border border-gray-200 shadow-sm">
<div class="text-md font-bold text-gray-900 mb-1">Mempool プライバシー</div>
<div class="text-sm text-gray-700">pending tx の binding 情報を見られないようにする提案</div>
</div>
</div>

<table class="text-sm mt-4">
<thead>
<tr><th>代表 PIR スキーム</th><th>特徴</th></tr>
</thead>
<tbody>
<tr><td class="font-bold text-amber-700">Spiral (MIT, Menon-Wu 2022)</td><td>hint-based、~100ms クエリ</td></tr>
<tr><td class="font-bold text-amber-700">SimplePIR / DoublePIR (Henzinger 2023)</td><td>hint をクライアントが保持、極めて軽い online 計算</td></tr>
<tr><td class="font-bold text-amber-700">FrodoPIR</td><td>lattice ベース、保守的パラメータ</td></tr>
</tbody>
</table>

<div class="mt-3 rounded border border-amber-300 bg-amber-50 p-3 text-md max-w-5xl">
🟡 汎用 vFHE (EagleEye) は重い。だが <strong>PIR のように応用文脈で限定された使い方</strong>なら既に実用域 &mdash; この対比が設計の勘所。
</div>
