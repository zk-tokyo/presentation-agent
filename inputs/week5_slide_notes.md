## 初学者向け改善メモ

ゴールを「TFHE の bootstrapping によるノイズ削減と HomNAND を理解する」と置く場合、現状のスライドは各部品の数式説明はあるが、部品同士の接続と最終目的がやや見えにくい。特に、受講者が追うべき主語を「暗号文」「ノイズ」「平文」「鍵」のどれに置けばよいかがスライドごとに変わるため、全体像を補助する必要がある。

### 2. 「ノイズが減る」という表現の中身が不足している

- 分かりにくい点:
  - Bootstrapping がなぜノイズ削減になるのかが、テスト多項式・回転・抽出の説明に埋もれている。
  - 実際には、入力暗号文のノイズをそのまま減算するのではなく、入力暗号文を「参照値」として使い、新しい暗号文を生成しているという見方が必要。
- 修正案:
  - 「ノイズを直接削る」のではなく、「暗号文から平文位置を読み取り、その位置の値を新しく暗号化し直す」という直感を入れる。
  - カード文言候補:
    - `Bootstrapping は、古い暗号文を使って同じ平文を持つ新しい暗号文を作り直す処理`
    - `入力暗号文のノイズは位置ずれとして吸収し、出力暗号文のノイズは新しい暗号化処理で決まる`

### 3. テスト多項式の役割が Lookup Table として見えにくい

- 分かりにくい点:
  - SL15 / SL15 b では多項式の係数配置を説明しているが、初学者には「なぜ多項式がテーブルとして使えるのか」が直感的に入りにくい。
  - 同じ平文を複数スロットに入れる理由が、ノイズ `e` の幅を吸収するためだと明示されていない。
- 修正案:
  - SL15 または SL15 b に「テスト多項式 = 回転できる Lookup Table」という一文を入れる。
  - 図では `m_0 | m_0 | ... | m_1 | m_1 | ...` のように同じ平文が複数スロットに渡ることを見せる。
  - 補足文候補:
    - `同じ平文を複数スロットに並べることで、少しのノイズで回転位置がずれても同じ値を取り出せる`

### 4. Blind Rotation の式と CMUX の関係が急に感じる

- 分かりにくい点:
  - SL17 で `Q_{j+1}=MUX(s_j,Q_j,x^{a_j}Q_j)` が出るが、なぜ `s_j` が 0/1 の選択ビットとして働くのかが初学者には見えにくい。
  - SL21 b の CMUX まで進むと、RGSW / external product / CMUX が一度に出て負荷が高い。
- 修正案:
  - SL17 の図やカードで、次の対応を明示する。
    - `s_j=0` なら回さない
    - `s_j=1` なら `a_j` だけ回す
    - これを全 `j` について積み上げると `as` の分だけ回る
  - SL21 b の前後で「CMUX は暗号文のまま行う if 文」という説明を入れる。
  - カード文言候補:
    - `CMUX は、秘密のビット s_j を見せずに「回す / 回さない」を選ぶための部品`

### 5. Sample Extraction の目的が「定数項を取り出す」だけに見えやすい

- 分かりにくい点:
  - SL23 / SL23 b では定数項の計算を説明しているが、なぜこれが LWE 暗号文になるのかを追うには前提が多い。
  - `a''` にマイナスが現れる理由は説明されているが、初学者には「結局何ができたのか」が後ろに流れやすい。
- 修正案:
  - SL23 の最初に「RLWE 暗号文の中の定数項だけを見ると、LWE 暗号文として扱える」という一文を置く。
  - SL23 b の図は、定数項へ寄与する項だけを強調し、他の項は薄く扱う。
  - カード文言候補:
    - `Sample Extraction は、回転後の RLWE 暗号文から、定数項だけを LWE 暗号文として切り出す処理`

### 6. Key Switching が bootstrapping の一部として見えにくい

- 分かりにくい点:
  - SL24 では式変形が中心で、なぜ Key Switching が必要かは書かれているが、全体の流れの中での役割が埋もれやすい。
  - Sample Extraction 後の鍵 `s''` と、最終的に使いたい鍵 `s` の関係が初学者には難しい。
- 修正案:
  - Key Switching の冒頭に「平文は変えずに、復号に使う鍵だけを戻す」という直感説明を入れる。
  - 式変形の前に、入力と出力を 1 行で固定する。
    - 入力: `LWE_{s''}(m)`
    - 出力: `LWE_s(m)`
  - カード文言候補:
    - `Key Switching は、暗号文の中身 m はそのままに、秘密鍵だけを s'' から s に戻す処理`

### 7. HomNAND への接続が必要

- 分かりにくい点:
  - Bootstrapping の説明だけだと、「なぜこれで NAND ができるのか」が別トピックに見える。
  - HomNAND では、bootstrapping が refresh だけでなく関数評価も兼ねる、というポイントを事前に橋渡しする必要がある。
- 修正案:
  - HomNAND の前に 1 枚、または HomNAND 冒頭に「Programmable Bootstrapping の使い方」を置く。
  - 伝えるべき要点:
    - 普通の bootstrapping: 同じ `m` を取り出すようにテスト多項式を作る
    - programmable bootstrapping: `m` ではなく `f(m)` が出るようにテスト多項式を作る
    - HomNAND: `f` として NAND を選ぶ
  - カード文言候補:
    - `テスト多項式の係数を変えると、refresh と同時に f(m) を出力できる`
    - `HomNAND は、NAND の値が定数項に来るようにテスト多項式を設計した bootstrapping`

### 8. 章全体の導線案

- SL15: テスト多項式は回転できる Lookup Table であることを強調する。
- SL15 b / c: 同じ平文を複数スロットに置く理由を、ノイズの幅と結びつける。
- SL16: `LWE_s(m) -> Blind Rotation -> Sample Extraction -> Key Switching -> LWE_s(m)` の出入り口を明示する。
- SL17 / SL21 b / SL22: CMUX は「秘密のビットで回す/回さないを選ぶ」部品だと繰り返す。
- SL23 / SL23 b: 定数項を取り出すと LWE 暗号文になる、という結論を先に置く。
- SL24 / SL24 b: 鍵を戻すだけで平文は変えない、と先に言う。
- HomNAND 前: `m` を取り出す代わりに `NAND(m_1,m_2)` を取り出す、という programmable bootstrapping の橋渡しを入れる。

## ファクトチェック上の注意

- TFHE は Chillotti, Gama, Georgieva, Izabachene らによる ASIACRYPT 2016 / Journal of Cryptology 2019 系の方式。
- FHEW は homomorphic accumulator を中心にした高速 bootstrapping の流れを作り、NAND/refresh を 1 秒未満で行う実装結果を報告した。
- TFHE の gate bootstrapping は、TLWE-to-TLWE bootstrapping、blind rotation、sample extraction、key switching を中心に説明するとよい。
- TFHE 論文の HomNAND の標準的な書き方では、メッセージを `{0, 1/4}` にエンコードし、`(0, 5/8) - c1 - c2` のような線形前処理をしてから bootstrapping する。
  - ただし Week 5 の資料では torus を避ける方針なので、スライド本文では整数 mod `q` にスケールした toy example として説明する方が自然。
- Programmable bootstrapping は「テスト多項式/LUT の係数を変えることで、refresh 中に評価する関数を変えられる」と説明するのがよい。
  - 任意の多変数関数の説明に Kolmogorov の重ね合わせ定理を持ち出すのは避ける。
  - 実用的には bit decomposition、circuit decomposition、LUT/gate composition で説明する。
